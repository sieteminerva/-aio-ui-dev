## 2. Use it from a browser (no bundler)

An import map cannot invent a `.js` suffix, so map the package root **and** every exact `exports`
subpath you import.

```html
<script type="importmap">
  {
    "imports": {
      "@aio-ui/core": "https://cdn.jsdelivr.net/gh/sieteminerva/-aio-ui-dev@v0.1.1/packages/core/dist/index.js",
      "@aio-ui/code-block": "https://cdn.jsdelivr.net/gh/sieteminerva/-aio-ui-dev@v0.1.1/packages/components/code-block/dist/index.js",
      "@aio-ui/code-block/CodeBlock.css": "https://cdn.jsdelivr.net/gh/sieteminerva/-aio-ui-dev@v0.1.1/packages/components/code-block/dist/CodeBlock.css"
    }
  }
</script>
```

Three ways to name the same tree:

| Ref | URL shape | When to use |
| --- | --- | --- |
| Tag | `…@v0.1.1/…` | default. Tag content never changes, so the browser/CDN cache is safe forever |
| Branch | `…@cdn/…` | follow the newest publish without editing the import map |
| Commit | `…@<full-sha>/…` | pin a specific build for a test or a rollback |

`https://raw.githubusercontent.com/sieteminerva/-aio-ui-dev/cdn/…` serves the same bytes and is the fallback
when jsDelivr is unavailable; it has no cache layer of its own, so expect plain HTTP caching only.

## 3. Install offline from the release assets

The packages are **not** on the npm registry, so `npm i @aio-ui/core` fails. Install the tarballs
attached to the release of this tag:

```bash
# 1. fetch the tarballs (one per package you use)
#    https://github.com/sieteminerva/-aio-ui-dev/releases/download/v0.1.1/aio-ui-<name>-0.1.1.tgz

# 2. install them into a normal project
mkdir my-app && cd my-app && npm init -y
npm i ./aio-ui-core-0.1.1.tgz \
      ./aio-ui-base-0.1.1.tgz \
      ./aio-ui-code-block-0.1.1.tgz
```

> **Declare the whole peer closure.** Components depend on each other through `peerDependencies`
> (`@aio-ui/base`, `@aio-ui/core`, `@aio-ui/utilities`, …). npm resolves a peer to a *locally
> installed* copy; a missing one sends npm to the registry and 404s. Read the package's
> `package.json` `peerDependencies` and install those tarballs too.
>
> Do not install `@aio-ui/frameworks` / `@aio-ui/modules` / `@aio-ui/themes` this way: the kits
> declare real `dependencies` on unpublished packages, so npm would go to the registry. Install
> the individual packages instead.

Verify the download before using it:

```bash
sha256sum -c checksums.txt          # 39 x OK, after downloading checksums.txt next to the tarballs
```

**Alternative — clone and build.** If you need the source, a debugger or a change:

```bash
git clone https://github.com/sieteminerva/-aio-ui-dev.git aio-ui
cd aio-ui
npm install          # workspace install
npm run build:pkgs   # writes dist/ for every TypeScript package
```

Then consume it with `file:` dependencies (`"@aio-ui/core": "file:../aio-ui/packages/core"`, one
entry per package, re-run `npm install` after every pull) or by adding the app to the workspace
(`examples/my-app`) so npm links every `@aio-ui/*` into `node_modules`.

## 4. Update to the newest publish

Tag refs are frozen. To move forward:

```bash
# a) follow the branch - nothing to edit, the next request revalidates
https://cdn.jsdelivr.net/gh/sieteminerva/-aio-ui-dev@cdn/packages/core/dist/index.js

# b) pin a new tag - replace v0.1.1 in the import map with the newest release tag
https://github.com/sieteminerva/-aio-ui-dev/releases        # newest tag + tarballs
npm i ./aio-ui-core-<new-version>.tgz             # offline installs: re-download, re-install
```

For a cloned workspace:

```bash
git switch main && git pull --ff-only
npm install          # only when a package or dependency changed
npm run build:pkgs   # dist/ is not tracked, so this always follows a pull
```

## 6. Tag immutability

jsDelivr answers a **tag** URL with `Cache-Control: public, max-age=31536000, s-maxage=31536000,
immutable` and pins the tag to the commit it first saw. Force-moving a tag therefore does *not*
change what `@<tag>` serves, not even after a purge. Every published version gets its own new tag;
`@cdn` and commit SHAs are the only refs that revalidate.
